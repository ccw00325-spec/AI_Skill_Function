# AI_Skill_Function — `Fun` 스킬

> “알아서 만들어 줘”라고 남겨 둔 빈칸을 AI가 대신 채우지 않게 하는 기능 명세·구현 스킬입니다.
> 빠진 결정은 질문으로 드러내고, 사용자가 답한 범위만 구현하고 문서로 남깁니다.

Claude Code에서는 `/Fun` 또는 `/fun`, Codex에서는 `$fun` 또는 `$Fun`으로 부릅니다.

---

## 왜 필요한가

“비밀번호를 5번 틀리면 로그인을 막아줘.”

짧은 요청이지만 빈칸이 많습니다. 몇 분 동안 막는지, 계정 단위인지 IP 단위인지, 연속 실패인지 누적 실패인지, 화면에는 무슨 문구를 띄우는지 아무것도 정해지지 않았습니다.
AI는 이런 빈칸을 학습 데이터에서 본 흔한 관례(예: “계정 단위로 30분”)로 조용히 채우곤 합니다. 그러면 사용자가 정한 적 없는 정책이 서비스에 들어가고, 그 사실은 나중에야 드러납니다.

`Fun`은 그 빈칸을 질문으로 꺼내 놓습니다. 사용자가 정한 것은 그대로 기록하고(이 예에서는 “5번”), 정하지 않은 것은 `미정`으로 남기고, 미정에 기대는 코드는 만들지 않습니다. 이 스킬은 기능의 결정권과 책임이 사용자에게 남도록 돕습니다.

## 핵심 공식

```
Function = Context + Trigger → Reaction
```

| 축 | 묻는 것 | 예 |
| --- | --- | --- |
| Context (Given, 조건·전제) | 동작 직전 시스템·사용자·데이터의 상태 | 로그인 상태, 잠긴 계정, 권한, 이전 실패 횟수 |
| Trigger (When, 행위·입력) | 동작을 일으키는 입력·조작·사건 | 버튼 클릭, 비밀번호 제출, 결제 승인 요청 |
| Reaction (Then, 결과·반응) | 화면·문구·데이터 변경·외부 효과 | 성공, 실패, 경계, 권한 부족, 지연, 중복, 복구 |

## 기능

### 세 가지 작업 모드

| 모드 | 이렇게 부르면 | 하는 일 |
| --- | --- | --- |
| 기능 제작 | `/Fun 로그인 화면 만들어줘` | 조건·행위·결과를 질문으로 확정하고 승인된 범위만 구현한 뒤 명세를 갱신 |
| 기존 기능 추출 | `/Fun 이미 구현된 전체 기능의 명세서를 만들어줘` | 프로젝트 파일을 읽고 기능별 현재 상태를 문서화. 코드는 고치지 않음 |
| 명세만 작성 | 문서만 요청 | 질문과 명세 작성까지만 진행 |

`/Fun`만 입력하면 셋 중 무엇을 할지 먼저 묻습니다.

### 질문하는 방식

- 첫 응답부터 가장 중요한 빠진 조건을 1~3개씩 묶어 묻습니다. 긴 목록을 한꺼번에 쏟아내지 않습니다.
- 선택지마다 결과와 영향을 설명하고 `직접 입력`·`보류`·`적용하지 않음`도 답으로 받습니다.
- 추천 표시나 첫 번째 선택지를 승인으로 치지 않습니다. 침묵, “다음으로”, “알아서 해줘”도 승인이 아닙니다. “알아서”라는 답을 받으면 적용하려는 결정 묶음을 구체적으로 보여 주고 범위를 확인합니다.
- 버튼을 스스로 만들지 않습니다. 버튼의 유무·이름·위치는 사용자에게 묻습니다.

### 기능별 명세 파일

명세는 프로젝트 안 `Function/` 폴더에 기능마다 따로 저장합니다.

| 기능 | 파일 |
| --- | --- |
| 로그인 화면 | `Function/login_fun.md` |
| 회원가입 화면 | `Function/Sign_fun.md` |
| 로그인 차단 정책 | `Function/login_lockout_fun.md` |
| 그 밖의 기능 | `Function/<feature_slug>_fun.md` |

파일마다 15개 항목(결정 기록, 미정 목록, Context·Trigger·Reaction 표, Gherkin 시나리오, 구현·미구현·제외, 검증, 한계, 리스크, 변경 이력 등)을 넣습니다. 같은 기능을 다시 다루면 기존 파일을 읽고 이전 결정과 사람이 직접 고친 내용을 지키면서 갱신합니다.

동작은 Gherkin으로 적고 태그로 출처를 나눕니다.

| 태그 | 뜻 |
| --- | --- |
| `@confirmed` | 사용자가 실제로 결정한 요구 |
| `@observed` | 기존 코드에서 관찰한 현재 동작(승인 아님) |
| `@pending` | 아직 정하지 않은 초안 |

### 세 축으로 나눈 상태

“완료” 하나로 뭉뚱그리지 않습니다.

| 축 | 상태 |
| --- | --- |
| 결정 | 승인됨 / 미정 / 제안·미승인 / 제외됨 / 충돌함 |
| 구현 | 구현됨 / 부분 구현 / 미구현 / 확인 불가 |
| 검증 | 검증 통과 / 검증 실패 / 미실행 / 확인 불가 |

“승인됐지만 아직 구현 안 됨”, “구현은 됐지만 검증은 안 돌림” 같은 상태를 그대로 드러냅니다.

### 예시 30개

스킬 본문에는 “비밀번호를 5번 틀리면 로그인을 막아줘” 한 문장에서 나올 수 있는 빈칸 30가지가 질문과 `@pending` Gherkin 초안으로 들어 있습니다. 적용 경로, 같은 계정의 기준, 연속과 누적, 다섯 번째 실패의 경계, 잠금 만료 순간, 잠긴 계정의 올바른 비밀번호, 관리자 계정, 고객센터 해제 절차, 동시 요청, 저장소 장애, 기록 항목과 민감정보, 알림 등을 다룹니다.
17번은 사용자가 직접 준 사례(30분 잠금과 안내 문구)를 원문 그대로 보존한 것이고 실제 프로젝트에 적용하려면 따로 승인을 받아야 한다고 못 박아 두었습니다.

## 장점

- **정하지 않은 정책이 코드에 섞이지 않습니다.** 시간, 횟수, 문구, 권한, 저장 방식처럼 서비스 동작을 바꾸는 값은 사용자 답이 있어야 들어갑니다.
- **승인과 관찰을 구분합니다.** 코드에서 30분을 발견하면 “현재 코드에서 관찰: 30분”으로 적을 뿐, “사용자가 승인: 30분”으로 바꿔 적지 않습니다.
- **반만 된 일을 다 됐다고 하지 않습니다.** 결정·구현·검증 상태가 따로 있어서 실행하지 않은 시험을 통과했다고 적을 자리가 없습니다.
- **결정 이력이 남습니다.** 결정 ID(`D-001`)와 시나리오 ID(`S-001`)를 이어 두어 무엇을 누가 왜 정했는지 나중에 찾을 수 있습니다.
- **기존 프로젝트 문서화에도 씁니다.** 읽은 파일과 못 읽은 파일을 나눠 적고 코드 모순과 결함 후보는 질문으로 돌려줍니다.
- **여러 AI 도구에서 같은 규칙을 씁니다.** 본문은 특정 도구 이름에 기대지 않는 Markdown이라 Claude Code, Codex, Gemini, Grok, 일반 채팅에서 같은 원본을 씁니다.

## 설치

저장소를 받습니다.

```bash
git clone https://github.com/ccw00325-spec/AI_Skill_Function.git
cd AI_Skill_Function
```

설치하기 전에 같은 이름의 스킬(`fun`)이나 명령(`/Fun`)이 이미 있는지 확인하세요. 아래 명령은 같은 이름이 있으면 덮어씁니다.

### Claude Code — `/fun`, `/Fun`

macOS·Linux·Git Bash:

```bash
mkdir -p ~/.claude/skills ~/.claude/commands
cp -r fun ~/.claude/skills/fun
cp fun/adapters/claude-code/Fun.md ~/.claude/commands/Fun.md
```

Windows PowerShell:

```powershell
New-Item -ItemType Directory -Force "$HOME\.claude\skills", "$HOME\.claude\commands" | Out-Null
Copy-Item -Recurse fun "$HOME\.claude\skills\fun"
Copy-Item fun\adapters\claude-code\Fun.md "$HOME\.claude\commands\Fun.md"
```

스킬 이름 `fun`은 `/fun`이 됩니다. 이름은 소문자로 정했습니다(스킬 검사 도구가 소문자만 허용합니다). 스킬만 설치했을 때 대문자 `/Fun`을 단독으로 입력하면 “명령이 없다”는 답이 나왔습니다(2026-10-06 시험). 그래서 `Fun.md` 명령 파일이 `/Fun`을 받아 `fun` 스킬로 넘깁니다. 규칙은 이 파일에 없고 `SKILL.md` 하나에만 있습니다.

### Codex — `$fun`, `$Fun`

macOS·Linux·Git Bash:

```bash
mkdir -p ~/.agents/skills && cp -r fun ~/.agents/skills/fun
```

Windows PowerShell:

```powershell
New-Item -ItemType Directory -Force "$HOME\.agents\skills" | Out-Null
Copy-Item -Recurse fun "$HOME\.agents\skills\fun"
```

Codex CLI·IDE에서는 `$fun`이나 `$Fun`으로 부르거나 `/skills`에서 고릅니다. Codex는 스킬 이름으로 슬래시 명령을 만들지 않습니다. 스킬이 로드된 대화 안에서 `/Fun ...`이라고 쓰는 것은 대화 약속일 뿐 시스템 명령이 아닙니다.

### 원본 하나로 두 도구에 함께 쓰기 (선택)

복사 대신 디렉터리 연결을 쓰면 한 곳만 고쳐도 두 도구에 같이 반영됩니다(Windows 예).

```powershell
New-Item -ItemType Junction -Path "$HOME\.claude\skills\fun" -Target "<저장소 경로>\fun"
New-Item -ItemType Junction -Path "$HOME\.agents\skills\fun" -Target "<저장소 경로>\fun"
```

### Gemini CLI (초안, 실행 미검증)

`fun/adapters/gemini-cli/Fun.toml`에 사용자 명령 형식의 어댑터 초안이 있습니다. 사용법과 확인하지 못한 점은 [`fun/adapters/README.md`](fun/adapters/README.md)에 적었습니다.

### 그 밖의 채팅 (ChatGPT, Gemini 앱, Grok, claude.ai 등)

`fun/SKILL.md` 내용을 프로젝트 지침이나 대화 첫 메시지로 넣은 다음 `/Fun ...`을 입력합니다. 이것은 대화 약속이지 명령 등록이 아닙니다. 파일을 쓸 수 없는 환경이면 명세 전체를 답으로 받아 직접 저장하세요.

## 한계

- **지침이지 강제 장치가 아닙니다.** 규칙은 모델이 지키므로 모델이 규칙을 어기면 막을 장치가 없습니다. 실제로 Codex(gpt-5.5) 시험에서 예시 값(30분)을 질문에 끌어오고 추천안을 내미는 일이 있었습니다. 환각을 완전히 없앤다고 주장하지 않습니다.
- **질문이 늘어납니다.** 결정을 미루지 않는 만큼 간단한 작업에서도 질문이 먼저 옵니다. 빠르게 시제품을 만들 때는 번거로울 수 있습니다.
- **본문이 깁니다.** `SKILL.md`는 약 890줄이고 예시 30개가 대부분을 차지합니다. 부를 때마다 그만큼 문맥을 씁니다.
- **검증 범위가 좁습니다.** Claude Code 2.1.290과 Codex CLI 0.152.0(Windows)에서 작은 예제로 한 번씩 확인했습니다. Gemini CLI와 Grok은 실행해 보지 못했습니다.
- **Claude Code의 `/Fun`은 명령 파일에 기댑니다.** `Fun.md`를 설치하지 않으면 대문자 호출은 동작이 보장되지 않습니다.

## 원문에 얼마나 충실한가

`SKILL.md`는 `spec/Fun_skill_creation_prompt.md`(원문 명세)를 바탕으로 만들었습니다. 규칙과 예시 30개는 다시 타이핑하지 않고 원문에서 잘라 붙였습니다.
원문과 다른 곳은 아래뿐입니다.

1. 원문 앞부분의 ‘제작 지시’와 13절 ‘제작 결과의 출력’은 스킬을 만드는 사람에게 하는 말이라 넣지 않았습니다. 대신 0절 ‘실행 순서 요약’을 덧붙였습니다.
2. 제작자에게 하는 말투였던 다섯 문장을 실행자에게 하는 말로 바꿨습니다(1절 두 문장, 3절·5절의 ‘프롬프트’를 ‘본문·스킬’로, 12절 제목).
3. 10절은 원문 규칙 9개를 그대로 두고, 앞에 능력 단위 표(프로젝트 읽기·질문하기·파일 쓰기·검증하기)를 덧붙였습니다.
4. `description` 끝에 호출 표현 한 문장(`/Fun, /fun, $fun, $Fun`)을 덧붙였습니다.

검사 실행:

```bash
python fun/scripts/verify_skill.py
```
